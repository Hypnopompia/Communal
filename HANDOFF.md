# Communal — Build Handoff

> Private, Napster-style file sharing for small communities: a self-hosted **hub** keeps the directory, and files move **directly between peers**. This document is the complete spec for building v1. Where it says "decide", make the call, record it in `docs/adr/`, and keep going.

---

## 1. Product summary

A desktop app (Electron) plus a headless Linux client, both connecting to a Linux hub server.

- Users join a hub with **no sign-up and no PII**: a display name and a device key.
- Users share folders. Each **folder or file** is visible to: **only me**, **specific people**, **groups**, or **everyone on the hub**.
- Users **connect** with each other (mutual, not called "friends"), can **verify** a connection with a safety code, and build their **own private groups** from their connections.
- A user's **own devices always see all of that user's files**, whatever the access rule.
- Others can **browse, search, preview thumbnails, download** files, and **subscribe** to folders (auto-download new files, with optional delete mirroring).
- Every uploader keeps a **local log** of who downloaded what.
- **No relay.** File data never touches the hub. If peers can't connect directly, the app tells the user why and how to fix it.
- **Any file type** is shareable; the app shows proper icons for all of them and thumbnails/previews for images, video, audio, and PDFs.

### Non-goals for v1
Mobile clients · hub-side thumbnail caching · any relay · admin UI for the connection graph · notifying owners of subscriptions · recovery-key prompt at first launch (export lives in settings only).

## 2. Decisions already made (don't revisit without asking)

| Topic | Decision |
|---|---|
| Accounts | No sign-up flow, no email/phone/password. Display name only. |
| Identity | Ed25519 device keys. First device's key = account root identity. Later devices carry a cert signed by an existing device of the same account. |
| Adding a device | First launch asks **New** or **Existing account**. Existing device generates a 10-minute single-use link code; the new device claims it; the existing device must **approve**; it then signs the new device's cert. |
| Recovery | Settings → Export recovery key (passphrase-encrypted file or word list). Restore option on fresh install. Not prompted at first launch. |
| Revocation | Any device of the account can revoke another. |
| Connections | Mutual request/accept. Either side can remove; removal revokes access granted through it immediately. |
| Verification | Safety code derived from both accounts' root fingerprints; compared out of band; "verified" flag stored client-side; loud warning if a verified root key changes. |
| Groups | Owned by a user, built from their connections, private to the owner (members can't see the group or each other through it). |
| Access rules | On folders or files. Files inherit from the nearest ancestor with a rule; a file's own rule overrides. New shares default to **Only me**. Audiences can combine people + groups. |
| Access privacy | Only the owner sees a file's rule. Nobody else learns who else has access. |
| Enforcement | Hub filters search/browse/sources/subscriptions by rules **and** the uploader re-checks rules before sending any byte. |
| Hub joining | Hub admin setting: open joining (default) or admin approval for new accounts. |
| Transfer path | Direct peer-to-peer only. No hub relay. Clear `connect.failed` diagnosis + tips. |
| Thumbnails | Generated by the owner's client, served peer-to-peer, cached by the viewer by hash. Hub never stores them. |
| Subscriptions | Add new files automatically. At subscribe time, ask "delete my copy when the owner deletes a file?" Default **no**. Changeable per subscription. Mirrored deletes go to OS trash. |
| Upload log | Local only (SQLite on the uploader). Never sent to the hub. |
| Mobile | Out of scope. |

## 3. Architecture

```
                 ┌───────────────────────────────┐
                 │  Hub (Linux, Node)            │
                 │  accounts · connections ·     │
                 │  index · search · presence ·  │
                 │  brokering · NO file data     │
                 └──────▲─────────▲─────────▲────┘
             wss (JSON) │         │         │
                 ┌──────┴───┐ ┌───┴──────┐ ┌┴─────────┐
                 │ Desktop  │ │ Headless │ │ Desktop  │
                 │ Electron │ │ Node CLI │ │ Electron │
                 │ + core   │ │ + core   │ │ + core   │
                 └────┬─────┘ └────┬─────┘ └────┬─────┘
                      └── direct, encrypted UDP ┘   (file chunks, thumbnails)
```

- **Hub**: Node + TypeScript. WebSocket server, SQLite (better-sqlite3, FTS5). Two UDP ports for NAT probing.
- **Core**: Node + TypeScript library/daemon. Indexing, type detection, metadata, thumbnails, hashing, hub session, peer transport, transfers, subscriptions, upload log. Exposes a **local API** (HTTP + WebSocket on localhost with a random bearer token, or a Unix socket) used by both UIs.
- **Desktop**: Electron. Core runs in an Electron `utilityProcess`; the renderer (React + Vite) talks to the core's local API.
- **Headless**: the same core under plain Node, managed by systemd, controlled by a `communal` CLI that calls the local API.

### ⚠️ Peer transport: spike first (Milestone 0)
The spec calls for an encrypted, mutually authenticated, UDP-based transport that supports hole punching. Node's built-in QUIC is experimental, so **spike before committing**:

1. `node:quic` (if stable enough on the current Node LTS)
2. A maintained QUIC binding for Node
3. `udx-native` (reliable streams over UDP) + Noise handshake (`@hyperswarm/secret-stream`)

Pick based on: hole punching works with **your own** signaling (not a DHT you don't control), no relay fallback baked in (or it can be disabled), Electron + Linux + macOS + Windows builds, and throughput on a 1 Gbps LAN. Whatever is chosen, both peers must authenticate with **device keys**, and the peer must verify the other's **device cert chains to an account**. Record the choice in `docs/adr/0001-peer-transport.md`.

## 4. Identity and crypto

- **Device key**: Ed25519, generated on first launch. Desktop: encrypted with `safeStorage`. Headless: file with mode `0600`.
- **device_id**: base32 of the first 16 bytes of BLAKE3(pubkey), prefixed `d_`.
- **Account root**: the first device's pubkey. **Fingerprint** = base32 BLAKE3(root pubkey), shown in groups of 4 characters.
- **Device cert**: `sign_existing_device(user_id ‖ new_device_pubkey ‖ issued_at)`. Store the chain: each cert names its signer. Verification walks back to the root key.
- **Revocation**: signed statement from any non-revoked device of the account; the hub distributes it; peers reject revoked certs.
- **Safety code** for a connection: sort both root fingerprints, BLAKE3 the concatenation, render as 4 groups of 5 digits.
- **Recovery key**: export the root private key, either as a passphrase-encrypted file (Argon2id + XChaCha20-Poly1305, or equivalent) or as a word list. Restore = a fresh device signs itself into the account with the root key and requests a cert record from the hub.
- **Hub key**: Ed25519. The client pins it on first contact and checks it on every connect (in addition to TLS). The hub signs transfer tokens with it.

## 5. Client ↔ hub protocol

Transport: `wss://<hub>/v1`, JSON text frames.

### Envelope
```json
{ "v": 1, "id": "m_01J…", "re": "m_01H…", "t": "search.results", "body": { } }
```
- `v` protocol major; unknown major → `error{code:"upgrade_required"}`.
- `id` sender ULID; `re` the id being answered; events omit `re`.
- Errors: `{"t":"error","re":"…","body":{"code":"forbidden","message":"…"}}`.

### Lifecycle
1. Connect → `challenge {nonce, hub_id}` → `auth {device_id, sig(nonce‖hub_id)}` → `welcome {session, observed_addr, index_rev, nat_probe_ports}`.
2. Client runs the NAT probe (section 8) and sends its network profile.
3. Index sync from `index_rev`.
4. `ping` every 30 s; drop after 90 s of silence. Presence goes offline only after the 90 s timeout.
5. Reconnect with jittered exponential backoff, 1 s → 60 s.

### Message catalog

| Type | Direction | Purpose |
|---|---|---|
| `account.create` / `account.created` | c→h→c | New account: `{display_name, device_name, device_pubkey, platform, client}` → `{user_id, device_id, fingerprint}` (or `pending_approval`) |
| `link.code.create` / `link.code` | c→h→c | Existing device gets `{code, expires_in:600}` |
| `link.claim` | new device → hub | `{code, device_name, device_pubkey}` |
| `link.request` | hub → existing device | `{device_name, platform, device_pubkey}` for approval |
| `link.approve` / `link.deny` | existing device → hub | `{cert}` |
| `link.done` | hub → new device | `{user_id, device_id}` |
| `account.restore` | c→h | Restore with recovery key: `{root_sig, device_pubkey, device_name}` |
| `device.revoke` | c→h | `{device_id, sig}` |
| `challenge` / `auth` / `welcome` | both | Session sign-in |
| `network.profile` | c→h | `{nat, upnp, ipv6, cgnat, lan_addrs}` |
| `user.search` | c→h→c | Find users on the hub by display name (to send connection requests) |
| `connection.request` / `connection.accept` / `connection.remove` | via hub | Manage connections |
| `connection.list` | c→h→c | Your connections and pending requests |
| `group.upsert` / `group.delete` / `group.list` | c↔h | Manage your groups |
| `acl.set` | c→h | `{device_id, path, audience}` |
| `index.snapshot` / `index.delta` | c→h | Report shared files |
| `index.ack` / `index.resync` | h→c | Confirm revision or demand snapshot |
| `search` / `search.results` | c→h→c | Search accessible files |
| `browse` / `browse.listing` | c→h→c | List a device's folder |
| `sources` / `sources.list` | c→h→c | Online accessible devices holding a hash |
| `watch` / `unwatch` / `watch.event` | c↔h | Folder subscriptions |
| `presence` | h→c | Device online/offline/address change (only for devices you can see) |
| `connect.request` / `connect.offer` / `connect.answer` / `connect.failed` | via hub | Broker direct connections |
| `ping` / `pong` | both | Keepalive |
| `error` | either | Request failed |

### Index sync
- A **share** is a named root folder. Local paths never leave the device; the hub only sees `ShareName/relative/path`.
- **Entry**:
  ```json
  {"path":"Movies/Alien (1979).mkv","size":4831838208,"mtime":1696118400,
   "mime":"video/x-matroska","kind":"video","meta":{"duration":7020,"width":1920,"height":1080},
   "thumb":true,"hash":null}
  ```
  `kind` ∈ image, video, audio, document, archive, code, text, disk_image, other.
- **Delta**: `index.delta {base_rev, rev, upsert:[entries], remove:[paths]}` → `index.ack {rev}`; mismatch → `index.resync` → client sends `index.snapshot` in pages of ~5,000 (`page`, `last:true`).
- Metadata first, hash later: background hashing emits `upsert`s that fill `hash`. Downloads are offered only for entries with a hash.
- Watch share roots (chokidar), batch deltas every few seconds, full rescan on startup.

### Search, browse, sources
- `search {q, kind?, min_size?, limit, cursor}` → hits **grouped by hash**: `{hash, name, size, mime, kind, meta, thumb, sources:[{device_id, owner, path, online}]}`.
- `browse {device_id, path}` → `{online, dirs, files}`.
- All filtered by access rules for the caller's **account**; own devices see everything. Files you can't access never appear, not even as counts.
- Search: SQLite FTS5 on file name; index on `hash`.

### Subscriptions
- `watch {device_id, path, recursive, mirror_deletes, since_rev}` → `watch.event {device_id, path, rev, added:[…], removed:[…]}`.
- Client downloads accessible files it doesn't already have (by hash), queues when the owner is offline, catches up from `since_rev` after being offline.
- `mirror_deletes` is chosen in a prompt at subscribe time (default false), editable later; deletes go to OS trash.
- Losing access stops new downloads; existing files remain.

## 6. Access control model

```
audience := "me" | "hub" | { users?: user_id[], groups?: group_id[] }
```
- Rules on folder or file paths within a share. Effective rule = the file's own rule, else the nearest ancestor folder's, else the share default (`"me"`).
- Visible to requester **R** for an owner **O**'s file if: R == O; or audience == "hub"; or R ∈ users and R is connected to O; or R ∈ a listed group of O (and still connected).
- Connection removal → instant loss of access via users/groups.
- **Hub** enforces on: search, browse, sources, watch, connect.request.
- **Uploader** enforces again on `hello`, `thumb.get`, `get`, using its own copy of its rules plus connection/group state synced from the hub.
- Never reveal the audience of a file to anyone but its owner.

## 7. Peer protocol

Mutually authenticated by device keys over the chosen transport (section 3 spike). Length-prefixed frames, msgpack headers, raw bytes for data.

| Frame | Direction | Content |
|---|---|---|
| `hello` | down→up | Hub-signed token `{session_id, from, to, hash, exp}` |
| `manifest.get` / `manifest` | down↔up | `{hash, size, chunk_size: 1 MiB, chunk_hashes[]}` |
| `get` | down→up | `{hash, ranges:[[start,end],…]}` (chunk indices) |
| `chunk` | up→down | `{index}` + bytes |
| `cancel` | down→up | Ranges to stop |
| `busy` | up→down | `{retry_after_s}` |
| `thumb.get` | down→up | `{hashes[], size: 320 \| 1600}` |
| `thumb` / `thumb.none` | up→down | `{hash, mime:"image/webp"}` + bytes / not previewable |
| `peek` | down→up | First 64 KB of a text/code file |

Uploader checks on `hello`: hub signature, `exp`, `to` == self, `from` == authenticated peer key, cert chain valid and not revoked, access rule allows.

- **Verification**: chunk-hash list must hash to the root; each chunk is checked on arrival; bad chunks are re-requested, preferably from another source.
- **Resume**: write to `Name.ext.part` + sidecar bitmap; on restart request only missing ranges; rename on completion.
- **Multi-source**: `sources {hash}` → connect to online sources → windows of ~32 chunks per peer; reassign a slow or dead peer's ranges.
- **Streaming**: in-order range requests a few chunks ahead (used for video/audio preview).
- **Uploader limits**: bandwidth cap, max concurrent uploads (default 3), "only upload on LAN" toggle.
- **Upload log** (uploader's local SQLite): timestamp, requester user + device, file path + hash, bytes sent, completed/partial/cancelled, kind (file/thumbnail batch). Configurable retention. UI list filterable by person/folder; `communal log` on CLI.

## 8. Connection brokering and diagnostics (no relay)

1. Downloader → `connect.request {target, hash, session_id}`.
2. Hub checks access, mints signed token (5 min expiry).
3. Hub → target `connect.offer {session_id, from, token, candidates}`. Candidates: LAN addrs, hub-observed public addr, UPnP/NAT-PMP mapped port.
4. Target → `connect.answer {candidates}` → forwarded.
5. Simultaneous dial over UDP; IPv6 first when both have it; LAN wins on the same network.
6. No path in ~10 s → both send `connect.failed` with observations; hub returns one diagnosis to the downloader:
   ```json
   {"t":"connect.failed","body":{"session_id":"x_…","cause":"both_restrictive_nat","easier_fix":"them",
     "you":{"nat":"symmetric","upnp":false,"ipv6":false,"cgnat":false},
     "them":{"nat":"symmetric","upnp":true,"ipv6":false,"cgnat":false}}}
   ```

**NAT probe**: hub listens on two UDP ports. Client sends from one local socket to both; same observed external port → endpoint-independent mapping; different → symmetric. Also record UPnP/NAT-PMP success, global IPv6, and router external IP in 100.64.0.0/10 (CGNAT).

| `cause` | User message | Tips |
|---|---|---|
| `peer_offline` | The owner's computer went offline. | Queued; resumes when they're back. |
| `both_restrictive_nat` | Neither network accepts incoming connections. | Enable UPnP on either router, or forward the app's port (shown in Settings) on one side. |
| `cgnat` | Your internet provider shares one public address among customers. | Ask for a public IPv4, enable IPv6, or have the other person forward a port. |
| `udp_blocked` | This network blocks the traffic the app needs (common on work/school/hotel Wi-Fi). | Try another network. |
| `os_firewall` | Your computer's firewall blocked the app. | Allow the app in Windows Defender Firewall / macOS firewall settings. |

Only one side needs to be reachable. `easier_fix` tells the UI whose setup to point at; offer a short help link to send to that person. **If any library adds relay fallback (e.g., DERP), disable it.**

## 9. File types, metadata, thumbnails

- Detect by magic bytes (`file-type`), fall back to extension; output `mime` + `kind`.
- Icons: map MIME → icon via a broad icon set, with sensible defaults per `kind`.
- Metadata during indexing:

| Kind | Tool | Fields |
|---|---|---|
| Image (JPEG, PNG, WebP, HEIC, GIF, RAW) | sharp / exifr | width, height, taken_at |
| Video | ffprobe | duration, width, height, codec |
| Audio | music-metadata | artist, album, title, duration |
| PDF | pdf.js | pages, title |

- Thumbnails: 320 px WebP (~10–30 KB), keyed by file hash, generated in the background after hashing. Video frame at ~10 % of duration; PDF page 1; audio embedded cover art. **Strip all EXIF/GPS.** Larger 1600 px preview on demand.
- Viewer caches thumbnails by hash on disk (LRU, size-capped).

## 13. Local development with Docker

Developers must be able to run the hub and several headless clients locally with one command, on macOS, Windows, or Linux, without a separate Linux server.

### Images
- `docker/hub.Dockerfile`: the hub. Publishes the WebSocket port and both NAT-probe UDP ports. SQLite on a named volume.
- `docker/headless.Dockerfile`: the headless client (Node + core + `communal` CLI), including ffmpeg and sharp's native deps so thumbnails work. Runs the core as PID 1 under a small init (`tini`), with the local API exposed only inside the container. The same image is the production image for NAS/server installs.
- Multi-stage builds from the pnpm workspace; images under ~300 MB where practical; amd64 and arm64.

### `docker/compose.dev.yml`
```yaml
services:
  hub:
    build: { context: .., dockerfile: docker/hub.Dockerfile }
    ports: ["8443:8443", "3478:3478/udp", "3479:3479/udp"]
    volumes: [hub-data:/data]
    environment: { COMMUNAL_JOIN_MODE: open, COMMUNAL_DEV_TLS: "self-signed" }

  node-a:
    build: { context: .., dockerfile: docker/headless.Dockerfile }
    environment:
      COMMUNAL_HUB: wss://hub:8443/v1
      COMMUNAL_DISPLAY_NAME: alice
      COMMUNAL_AUTO_INIT: "true"        # dev only: create an account on first start
      COMMUNAL_PEER_PORT: "41641"
      COMMUNAL_ADVERTISE_ADDR: "127.0.0.1:41641"   # host-reachable candidate for the desktop app
    ports: ["41641:41641/udp"]
    volumes: [node-a-data:/var/lib/communal, ./fixtures/alice:/shares/alice:ro]

  node-b:
    # same as node-a with name "bob", port 41642, ./fixtures/bob

volumes: { hub-data: {}, node-a-data: {}, node-b-data: {} }
```
- `docker compose -f docker/compose.dev.yml up` brings up a hub and two clients that can find, connect to, and download from each other on the compose network.
- The CLI runs inside a container: `docker compose exec node-a communal share add /shares/alice --name Photos`, `… communal acl set Photos/ hub`, `… communal transfers`.
- `COMMUNAL_AUTO_INIT` and `COMMUNAL_DEV_TLS` are dev-only conveniences, ignored in production builds.
- `pnpm dev:stack` wraps compose; `pnpm dev:stack:reset` wipes volumes for a clean run.

### Desktop app against the dev stack
The Electron app runs on the host and points at `wss://localhost:8443/v1`. Containers' internal addresses aren't reachable from the host on macOS/Windows Docker, so each dev client advertises a host-reachable candidate via `COMMUNAL_ADVERTISE_ADDR` with its UDP port published. Candidate lists must support an operator-supplied advertise address for this reason (it's also useful for production port-forward setups).

### Simulating bad networks (later, Linux CI)
An optional `compose.nat.yml` puts clients on separate networks behind small NAT/firewall containers (iptables) to reproduce symmetric NAT, blocked UDP, and offline peers for the M5 diagnostics tests.

## 14. Engineering conventions

- TypeScript strict mode everywhere; all wire messages validated with zod at boundaries.
- The core never depends on Electron; Electron only hosts it.
- Every hub handler has an access-control unit test.
- Never log file contents, keys, tokens, or full local paths at info level.
- Structured logs (pino) with a `session_id` / `transfer_id`.
- Keep a running `docs/progress.md` and add an ADR for every non-obvious choice.
- If a requirement here turns out to be impossible or a bad idea, stop and write it up in `docs/questions.md` rather than silently diverging.
