# Security audit, October 2026

- Date: 2026-10-14, at version 0.1.6.
- Scope: the hub (`apps/hub`), the protocol schemas, and the client engine, local API, peer transfers and desktop shell (`packages/core`, `apps/desktop`). The question was: what could a stranger, a member of the same hub, or another program on the same computer do that they shouldn't?
- Method: reading the code against those three attackers. Nothing here comes from a fuzzer or an outside tester.

## Fixed in this change

ADR 0022 has the details and the numbers.

| #   | Finding                                                                                                                                                                             | Severity | Fix                                                                                                                 |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------- |
| 1   | No limit on accounts per address. A script could fill an open hub with accounts.                                                                                                    | High     | `signups_per_hour` per address (IPv4, or IPv6 /64), adjustable by the admin.                                        |
| 2   | No limit on index size. One device could upload millions of entries with 4 KB paths. A root-key holder can also certify any number of devices offline, each with its own index.     | High     | `max_files_per_device` and `max_devices_per_account`.                                                               |
| 3   | No request budget. One signed-in session could run searches, browses and `connect.request` as fast as the hub could answer.                                                         | High     | A token bucket per session. Over budget, messages wait instead of failing. Sessions that keep piling on are closed. |
| 4   | An unauthenticated connection could stay open forever by pinging: the auth timeout counted from the last message.                                                                   | Medium   | The timeout counts from the connection.                                                                             |
| 5   | No limit on connections per address.                                                                                                                                                | Medium   | 20 per address.                                                                                                     |
| 6   | The UDP probe responder answered any datagram of 64 bytes or less with a reply about 4× larger, which made it usable for reflection with spoofed sources.                           | Medium   | It answers only the client's exact probe, 10 replies a second per address.                                          |
| 7   | Every repeated `connection.request` notified the target again, so a request could be used to nag. Outstanding requests were unlimited.                                              | Medium   | A repeat changes nothing. At most 50 requests waiting per account.                                                  |
| 8   | Unbounded groups per account, rules per device (`acl.set` accumulates), stored subscriptions (the cap of 1,000 counted only the live session) and brokered connections per session. | Low      | Fixed caps.                                                                                                         |
| 9   | A banned account could still add devices (they couldn't sign in, but the rows piled up).                                                                                            | Low      | Refused with `banned`.                                                                                              |
| 10  | Names could carry bidirectional overrides or control characters, so `Bob` could display as someone else, and a file named `photo\u202egpj.exe` would read as `photoexe.jpg`.        | Low      | The hub refuses such names from clients, and `safeName` strips overrides from downloaded file names.                |

## Open

Each of these has a Backlog entry in `docs/progress.md`, or a question in `docs/questions.md` where it needs the owner.

| #   | Finding                                                                                                                                                                                                                                                                                                                                                                                                                           | Severity | Suggested fix                                                                                                                                                                                                         |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A   | **No way to block someone.** Removing a person's request lets them send a new one right away. With finding 7 fixed, each new request still notifies you once.                                                                                                                                                                                                                                                                     | Medium   | A per-hub block list: requests from blocked users are dropped silently. Needs an owner decision (question in `docs/questions.md`).                                                                                    |
| B   | **Brokering reveals addresses and lets a peer aim your punches.** Anyone who can see one of your files can ask for a connection and learn your device's public and LAN addresses from `connect.answer`. Direct transfers need some of this exposure, but not all of it. | Medium   | Have the uploader skip LAN candidates unless both sides share a public address, and refuse candidates in loopback, link-local and multicast ranges. Send LAN candidates only to peers behind the same public address. |
| C   | **The app shows other people's file names as they are.** Names with direction overrides look misleading in Search, Browse and Transfers, even though they're saved safely.                                                                                                                                                                                                                                                        | Low      | Strip or mark overrides when rendering untrusted names in the renderer.                                                                                                                                               |
| D   | **Installs and Windows updates rely only on GitHub's HTTPS.** `site/install.sh` downloads release assets without checking a checksum or signature. The Windows build is unsigned, so electron-updater has no publisher to check. macOS updates are signed and notarized.                                                                                                                                                          | Low      | Publish `SHA256SUMS` with each release (signed, ideally) and check it in `install.sh`. | E   | **The Windows local API pipe has no token,** and its name can be derived from the data path. Another user on the same Windows machine could create the pipe before the app starts, so the CLI or an agent would talk to an impostor. The default pipe ACL should stop other users from connecting, but we haven't tested that.                                                                                                    | Low      | Create the pipe with an explicit owner-only DACL, and check the server's identity, or require the token on the pipe too.                                                                                              |
| F   | **Waiting accounts pile up.** In approval mode, sign-ups from many addresses can still flood People › Waiting.                                                                                                                                                                                                                                                                                                                    | Low      | Expire waiting accounts after a while (a hub setting), and let the admin clear the list in one step.                                                                                                                  |
| G   | **Agents read other people's text.** MCP tools return file and display names written by other people, which is a prompt-injection path into an AI agent. The tools that change access already need `preview_access` and the user's confirmation.                                                                                                                                                                                  | Low      | Mark untrusted fields in tool results, and keep every tool that changes something behind a confirmation.                                                                                                              |

## Accepted as designed

- **Limits are per address.** Someone with many addresses gets through them. Approval mode is the defense for a hub whose address gets around (`docs/questions.md`, "Ban evasion").
- **Any member can list everyone** on the hub through people search (names and fingerprints). That's how people find each other. Approval mode decides who is a member.
- **`account.restore` says whether an account with a given root key is on this hub.** Members see root keys anyway, in every `UserSummary`.
- **The hub sees metadata:** who shares what with whom, file names, sizes and hashes. It never sees file contents, thumbnails or download history (HANDOFF §2).

## Checked, and found sound

- **Access control** is enforced twice. `Catalog.visible()` is the only filter on the hub. The uploader re-checks every `hello`, `thumb.get` and `get` against the device's own rules and a hub-signed token for that exact session.
- **Identity:** clients verify every `UserSummary` against its root key, and peers check cert chains and revocations after the Noise handshake. A malicious hub can hide people but can't impersonate them.
- **Inbound peer traffic:** udx streams exist only for brokered sessions, so nothing is accepted on the UDP socket unless the hub brokered it and the token checks out.
- **Downloads can't escape their folder:** every path segment goes through `safeName`, which keeps only a base name and refuses `.` and `..`. That covers single files, folder downloads and subscriptions.
- **The local API** needs the bearer token over TCP, compared in constant time. The Unix socket is mode 0600 in a 0700 data directory. Key and account files are written 0600.
- **The Electron renderer** runs with `sandbox`, `contextIsolation` and no Node. Navigation is blocked, new windows open only `https:` URLs externally, the CSP allows only bundled scripts, and no `innerHTML` is used. The renderer never sees the API token.
- **Hub messages** are validated by zod schemas with length caps on every string and array, and frames are capped at 8 MB.
